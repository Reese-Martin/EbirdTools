# National 2024 EBD import

This pipeline is prepared for the authorized download. Fixture tests cover
import, source retention, policy scoring, complete candidate construction and
independent validation of a small fictional route. The real release has not
been imported, reconciled or benchmarked yet.

On a fresh clone, first follow the [machine handoff guide](MACHINE_HANDOFF.md).
The frozen countability policy and land-mask inputs live in ignored local
directories and must be restored separately before running this command.

## Run after the download arrives

From the repository root, supply the actual download path and release label:

```sh
bigyear/.venv/bin/python bigyear/scripts/import_ebd_2024.py \
  --source "/path/to/approved-download.zip" \
  --sed-source "/path/to/approved-download.zip" \
  --release "actual-EBD-release-label" \
  --output bigyear/data/ebd-lower48-2024
```

Include `--sed-source` when Sampling Event Data is present in that ZIP. It may
instead point to a separate SED `.txt`, `.tsv` or `.gz` file from the same release.
Omit it if SED was not supplied; EBD checklist/group identifiers and effort
columns are still retained. ZIP members are selected by their headers. Use
`--member` / `--sed-member` if there are multiple matching exports.

Local `.tar` and `.tar.gz` archives are also supported, including EBD/SED
`.txt.gz` members inside them. Supply the tar path to `--source` and, if the
same archive includes SED, `--sed-source`. The reader opens members as streams;
it never extracts the tar or creates a full decompressed text file. Member
selection uses EBD/SED headers and refuses an ambiguous archive. A selected
member must be a regular file; archive links/devices are not followed.

For example, for a locally available world archive:

```sh
bigyear/.venv/bin/python bigyear/scripts/import_ebd_2024.py \
  --source "/path/to/world-EBD.tar" \
  --release "actual-EBD-release-label" \
  --output bigyear/data/ebd-lower48-2024
```

This command accepts **local files**, not HTTP URLs. If the archive itself does
not fit locally, filtering during download is a separate transport path to
configure after checking the actual URL, authentication, archive layout and
server resume/range support. Such a stream can discard out-of-cohort rows
without ever storing the world archive, but still has to transfer/decompress
and inspect the relevant data member. Plain-text filtering cannot skip unwanted
rows within a single gzip stream without reading them. No global-size runtime
or storage estimate has been measured yet. Retain the frozen release metadata,
subset checksums and import audit if the original is not kept locally.

The script uses the existing local OSM land shapefile and frozen countability
sources. It requires no downloads or credentials. The optional `--land-mask`
accepts an EPSG:4326 land-polygon `.shp` (with `.shx`) or a smaller GeoJSON land
mask. A state outline includes water and is not a substitute for the land mask.
The shapefile reader requires the existing `gis` optional dependency (`pyshp`).

The national configuration is `examples/ebd-2024-national.json`: full calendar
year, one shared 12-hour activity budget, 2-hour birding stops,
`mixed_road_birding: true` and walking at **2.2 km/h**. Ordinary driving,
birding and walking share the twelve-hour budget without a road-mile cap.
Driving-only dates can use twelve hours; a two-hour birding visit leaves at
most ten hours for driving and any required walking.
The legacy `local_miles: 30` setting remains for older runs and boat-day access.
The full road-anchor gap is walked out and
back when it exceeds 100 m. Import refuses a configuration that silently changes
those rules or requests a reduced candidate capacity. Flights, modeled charter
trips and island landings remain separate routing inputs; import does not start
a search or infer a boat journey from walking distance.

Add `--resume` to the same command after interruption. Completed source windows
are replayed and hash-checked; completed archive/land stages are verified rather
than appended a second time. Inputs, release, members and configuration must
match the original import plan. A completed dataset can be reused. If an
interruption leaves an uncheckpointed `land.csv` or an incomplete `dataset/`,
inspect/move aside that specific incomplete artifact before resuming. Never
remove the original download or an existing EOD dataset to resume this import.

## Retention and scoring

The archival cohort uses only observation year **2024**, `COUNTRY CODE=US`, and
the 48 contiguous states plus DC in `STATE CODE`. Alaska, Hawaii, territories,
other countries and other years are outside this cohort. State-attributed
offshore observations remain included; no terrestrial polygon is applied to
the archive. An invalid observation date or unresolved US jurisdiction stops
conversion for review rather than quietly losing a potentially relevant row.

Every supplied column and every selected row is preserved as text, including
duplicate observation IDs/rows, shared checklists, incomplete/incidental
checklists, unapproved records, hybrids, held taxa, comments, effort fields,
observer identifiers and marine records. There is no effort, protocol,
completeness, rarity or coordinate rounding filter. A trailing blank header is
named `_ebd_trailing_blank`; the original header list remains in the manifest.
`_source_row` provides a stable source-row number. Quotes in TSV fields are
literal text. Malformed TSV rows stop the import; errors are not ignored.

Each bounded window is written as Zstandard level 3 Parquet and every retained
field is compared after reading the part back. SHA-256 binds each output part,
every source window, the complete decompressed stream and the original source
file/ZIP. Original latitude/longitude strings remain intact even where distinct
decimal strings map to the same double-precision number. Exact strings also
remain in the complete EBD location catalog. Numerical routing coordinates are
derived without deliberate rounding. Reported checklist coordinates do not
certify each bird's physical position; sensitive/generalized points are not
reconstructed or moved.

The derived dataset uses policy
`lower48-2024-primary-plus-documented-provisionals-v3`. Primary and provisional
tiers, state/population/date envelopes and existing holds remain distinct.
Only exact frozen scientific-name **and Avibase concept** matches map
automatically. The duplicated `avibase-avibase-` transport prefix in the EOD
crosswalk is normalized; no biological taxonomic change is inferred. A changed
name, new concept, split, lump or previously unseen taxon goes to review. The
current crosswalk reflects concepts audited in EOD; it is not an assertion that
EBD contains no additional countable species.

Scoring requires publisher approval and positive presence (`X` or positive
count), an explicitly mapped taxon and support under the frozen policy.
`REVIEWED=1` is not required. Escapee `X` and explicit captive/aviary/rehabilitation
remarks are held. Exotic `P` receives automatic credit only in an existing
provisional tier and its dated population envelope; unknown codes are held.
An eBird exotic label does not expand the frozen ABA policy. GBIF approvals for
individual records are frozen for provenance but do not transfer to EBD records.
Held taxa require EBD-specific review before receiving credit.

Access remains separate from countability. Countable observations outside the
land mask stay in `ebd_countable_evidence` with
`marine_or_island_access_review`. The terrestrial `dataset_evidence` and
`dataset_observations` views require land classification. New EBD marine/island
observations need exact dated vessel/landing support before joining a route;
old EOD record IDs, road-cost cache entries and boat variants are not relabeled
as EBD evidence. Unsupported access receives no routing credit.

SED joins use **SAMPLING EVENT IDENTIFIER**, never coordinates. Duplicate SED
rows cannot multiply observations; conflicting group identifiers stop the
join. Group events are labeled consistently, while all observer/checklist
records remain in the archive. Only the candidate model coalesces species credit
at a date and exact location; it retains the source row count and source evidence.

## Outputs and storage

The new output directory contains:

- `observations/`: verified Parquet parts and source accounting manifest.
- `sampling/`: optional independently verified SED archive.
- `land.csv`: exact-string point classifications for access review.
- `dataset/manifest.json`: frozen policy/input hashes and reconciliation counts.
- `dataset/review.csv`: held taxa/quality dispositions with counts and date range.
- `dataset/taxon-inventory.csv`: every concept and its scoring/access dispositions.
- `import-plan.json`, `stages.json`, `import-report.json`: resume bindings and audit.

Raw observations stay in one Parquet archive. Dataset views read it directly;
there is no second full evidence/observation copy. Conversion uses 32 MiB source
windows with a bounded final record, a 1 GiB DuckDB memory limit and bounded
temporary spill. It pauses below 3 GiB free disk and is resumable. Land geometry
is processed one 5-degree tile at a time, with point results streamed in batches.
Model construction uses the 3 GiB configuration limit and bounded spill.
These are query budgets, not a measured nationwide peak-RSS guarantee.

Temporary windows, pending files and managed DuckDB spill are cleaned on normal
completion or handled errors. A hard process kill may leave the current bounded
window/pending part; resume replaces it, and managed spill cleanup reclaims dead
planner-owned query directories. Verified parts intentionally accumulate as the
retained archive. Original downloads, audit files, land classification and model
components are kept. The importer does not delete existing inputs or old runs.
Actual final size and runtime depend on the approved release; measure them from
the import report rather than extrapolating from the tiny fixtures.

Verify the archive and retained original independently:

```sh
bigyear/launch.sh inspect-ebd \
  --archive bigyear/data/ebd-lower48-2024/observations \
  --source "/path/to/approved-download.zip"
```

After reviewing coverage and taxonomy/access holds, add `--resume --build-model`
to the original script command to build all eligible terrestrial candidates, or:

```sh
bigyear/launch.sh prepare-complete \
  --dataset bigyear/data/ebd-lower48-2024/dataset \
  --config bigyear/examples/ebd-2024-national.json \
  --output bigyear/data/ebd-lower48-2024/model
```

This complete model uses the existing memory-mapped planner architecture. It
does not use the legacy `prepare` command's location selection. Before the next
national driving/flight/boat benchmark, audit release-specific taxonomy changes,
state/month coverage, held observations and marine/island support, then repeat
the county/state validation with EBD evidence. Import is ready; real EBD
scientific validation remains pending the download.
